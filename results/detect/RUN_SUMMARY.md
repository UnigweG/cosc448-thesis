# D2 v3 overnight run summary

Branch `d2-v3`, no push. Scoring ran 2026-10-28 (about 7.6 h on the M4 Pro, mps, float16). All numbers here are read from the produced CSVs.

## What ran
- **SonarQube 26.9** for 2022 (4 repos) and 2026 (capstone, n=1): `results/sonar_2022.csv`, `results/sonar_2026.csv` (same columns as `results/sonarqube_metrics.csv`), status in `results/sonar_scan_status_2022_2026.csv`. 2023-25: the 68 existing server projects were reused (clone HEAD equals the scanned SHA for all 68, none rescanned).

- **Detectors** (local, offline): Binoculars-style with Qwen2.5-Coder-1.5B (observer) + Qwen2.5-Coder-1.5B-Instruct (performer); DroidDetect-Large-Binary. 15,290 files, 19,886,784 Qwen tokens, 0 failures (`failed.csv` is empty; the retry pass had nothing to retry).
- Outputs: `file_inventory.csv` (74,098 candidates), `file_level*.csv`, `repo_level*.csv`, `DATA_DICTIONARY.md`, `manual_kit/` (365 files, 73 repos x up to 5), `verification.md`. Raw per-chunk tables are in `data/detect/detect.sqlite` and `results/detect/chunks/*.csv.gz` (both git-ignored).

## Decisions and deviations from the brief
- **2022 `database` was NOT skipped.** The brief said it has no source files, but it has 32 tracked files including 30 PHP files (PHP is on the language list). It was scanned and scored as a 4th 2022 repo, so 2022 is **n=4**, not 3. Drop it by filtering `repo != 'database'` if unwanted.
- `matlab-to-python-...-nrc` contains no `.m` files (87 Python files); no MATLAB was scored beyond 2 stray `.m` files elsewhere.
- Capstone `git pull --ff-only` succeeded (clean fast-forward); scanned SHA `d04513376a8bb046584604177a802a4409ae85b4`. Local clones under `data/repos/2022|2026/` with push disabled; originals untouched.
- `hot-desking-deploy`: `src/public/packages/**` (ckeditor, tinymce, etc., 2,890 files) was excluded from both the Sonar scan and the detector inventory.
- Exclusions, applied to the detector inventory (reason per file in `file_inventory.csv`): Sonar directory/min.js rules (54,874), vendored packages (2,890), vendor/bower_components/third_party dirs (293), generated headers (201), `.d.ts`/pb2/etc. (106), generated report HTML (106), minified/data (49), vendored library banners such as p5.js/Bootstrap (18), empty (209), under 8 tokens (61), binary (1). The detector-only exclusions (everything except the Sonar ones) were not applied to the 2023-25 Sonar scans, so a few such files exist in Sonar but not in the detector table.
- **Audit of the `generated_marker_in_header` exclusion (201 files: 2023 100, 2024 73, 2025 28).** Matched text: "generated by" 111, "auto-generated" 64, "autogenerated" 14, "do not edit" 7, "@generated" 5. None of the 201 headers names an AI tool; the one file whose header line mentions "AI" (`2025/capstone-project-team-8`, `human_file_filter.py`) is a service that filters auto-generated files out. The rule is unchanged. It would still drop a file that starts with "Generated by ChatGPT"; no such file exists in this data.
- **Reproducibility.** `requirements.txt` pins torch, transformers, huggingface_hub, tokenizers and safetensors to the `.venv` that produced these results, and lists the Hugging Face revisions used (Qwen2.5-Coder-1.5B `df3ce67c`, -Instruct `2e1fd397`, DroidDetect-Large-Binary `44c45cbf`, ModernBERT-large config `45bb4654`). The revisions are not stored in the SQLite files table.
- `21_aggregate.py` keeps only score rows whose (year, repo, path, content_hash) is in the current included inventory, so a rerun after a repo changed cannot export stale or duplicate rows (rerun on the current data gives identical CSVs). It also keeps hand-filled `manual_kit.csv` columns when the kit is regenerated.
- Chunking: 512 Qwen tokens per Binoculars chunk, 510 content tokens (+CLS/SEP) for DroidDetect, cut at line ends in the last quarter of a chunk, tail of at least 32 tokens; file value = token-weighted mean of chunks. DroidDetect's model card gives no max length; 512 is used.
- fp16 on mps: checked against fp32 on 2022/database, max Binoculars difference 0.001 (correlation 0.99999), fp32 was 2x slower.
- Binoculars score = performer log-perplexity / cross-perplexity; **lower = more AI-like**. No threshold is applied. Percentile columns are ranks within this run only.
- Files with `droid_p_ai >= 0.5` get `MACHINE_GENERATED` (DroidDetect's own binary label).

## Caveats (read before analysis)
- **DroidDetect flags 59% of 2022 (pre-AI) files as AI.** The label is clearly not calibrated for student code; do not read label shares as AI prevalence without a baseline-based calibration. Use the 2022 baseline for that.
- The Qwen pair differs from the original Falcon-7B Binoculars; scores are not comparable to published thresholds.
- 2022 is n=4 repos and 2026 is n=1; year comparisons for these are descriptive only.
- Unsupported-language files (MATLAB, SQL, HTML, CSS) are scored but flagged `detector_language_supported = no`.
- SonarQube cannot analyse C# with the CLI scanner: 2,956 C# files are scored by the detectors but have no Sonar measures (`sonar_analysed = no`), as do 117 SQL files and a few others. Sonar-empty rates per column are in `verification.md`. For analysed files, missing issue counts were filled with 0.
- Third-party code committed without a recognisable banner (e.g. Unity packages, tree-sitter grammars in 2025 team-3) is still included.
- ZeroGPT and GPTZero were not called; fill `manual_kit/manual_kit.csv` by hand.
- Test files are included (see `is_test`).
